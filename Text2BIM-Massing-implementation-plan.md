Обновлён 5 ноября 2026. Этапы 1–5 завершены и проверены. Этап 6 выполнен
частично: есть отдельный runner, успешный Linux-пилот и адаптер полных
реальных требований одного здания;

## Текущий приоритет пользователя

Сначала нужен инструмент, способный **сгенерировать и оценить один массинг**.
Сборка всех компонентов вместе и сравнение методов выполняются позже.
Полный test split и серия benchmark-запусков не являются условиями готовности
этого инструмента и сейчас не запрашиваются.

Текущие критерии выполнены:

- [x] Принять одно текстовое задание/context или один JSON sample с requirements.
- [x] Построить непустой массинг через роли Text2BIM и сохранить геометрию/код.
- [x] Вызвать реальный внешний evaluator и привязать отчёт к snapshot.
- [x] Поддержать отдельный Reviewer-патч, повторную оценку и выбор кандидата.
- [x] Проверить Linux-запуск и сохранить статус, расходы, ошибки и provenance.

Проверенный одиночный кейс: CoMa 1627, 14 этажей, фактические цели по площади
и высоте из sample; отчёт четырёх исходных метрик и замкнутая mesh сохранены.
Для запуска используется `--sample`; прежний `--dataset` остаётся алиасом.

## Цель и неизменные требования

Самостоятельный Python-пакет для генерации массингов на Linux с внешним
оценщиком, подключаемый в репозиторий Маслова отдельным экспериментом.
Максимально сохранять исходные фрагменты Text2BIM, промпты и взаимодействие
Enhancer / Architect / Programmer / Reviewer. Architect вызывается по запросу.
Vectorworks/Solibri заменяются геометрией массингов и внешним evaluator.
Параметризацию и NSGA-II метода Маслова внутрь baseline не добавлять.

Каждое изменение — добавление, удаление, перемещение, зависимость или правка
промпта — фиксировать в [журнале адаптации](docs/text2bim-adaptation.md):
исходный commit/фрагмент → рабочее место → причина → влияние на метод →
проверка и её статус. Дополнять `docs/adaptation-spec.json`, формировать diff
и проверять хеши. Сохранять авторство и лицензионные уведомления.

Это адаптированный baseline. Совпадение качества с исходной статьёй не заявляется.

## Рабочий контракт

```python
result = generate(task, evaluator, llm, config, output_dir)
report = evaluator(massing, context)
```

- `massing` — список экструзий Маслова: `polygons`, `bottom_elevation`,
  `top_elevation`, все координаты и высоты в метрах.
- `context` — внешние данные задачи. Внешний evaluator возвращает JSON-словарь.
  Метрики, цели и направления улучшения задаются вне ядра; общего score нет.
- Разная вложенность `SampleMetric` / `SampleProcessor` задаётся тонким адаптером.
- Выход — архив кандидатов с фактическими отчётами, выбранный оценённый кандидат,
  код, история, расходы и статус. Частичный результат сохраняется при лимитах.

## Ограничения, которые нужно сохранять при доработке

- Исходный `SyntaxError` не должен давать ложный успех; `vs.py` — заглушки.
- Исходные промпты используют mm, внешний формат — m. Семантика плоских колец
  должна соответствовать Маслову, включая отверстия и отдельные компоненты.
- Оценка относится к неизменяемому snapshot. Изменение сцены требует новой оценки.
- Выбирать можно только оценённый кандидат. Повторное чтение отчёта не расходует
  новую оценку; неудачные попытки учитываются в бюджете.
- При исчерпании бюджета сохранять накопленный результат, даже без выбора.
- Физическая валидация не блокирует ядро с другим рабочим evaluator;
  перед физическим сравнением выбранные оценщики проверяются отдельно.
- Исполнитель ограничивает Python, но не предоставляет полноценную OS sandbox.
- Отсутствующие прежние материалы `text2bim-audit/pitfalls-and-validation.md`,
  `text2bim-audit/feasibility-and-priorities.md` и `our-method-vs-text2bim-adapted.md`
  не считать прочитанными или приложенными. При появлении включить их с provenance.

Этот план имеет приоритет над старыми проектными заметками.
