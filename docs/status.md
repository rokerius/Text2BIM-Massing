# Текущий статус

Состояние на **5 ноября 2026**. Версия пакета `0.1.0`, Python 3.11–3.13.

> **Standalone baseline готов.** Сценарий одного массинга — от задания до
> внешней оценки, патча и воспроизводимого результата — завершён.
> Приёмка checkpoints зафиксирована в версии `3adb6cb`; runtime интеграции
> закреплён на `49a047c`, содержащем исправление атомарности журнала.

Этапы 1–5 выполнены. Подготовлены отдельный runner и адаптер требований
для одного здания; подключение к общему launcher и сравнение на датасете
относятся к [следующему этапу](#следующий-этап).

## Исправление checkpoints после ревью

Восстановлены два дефекта: весь source после commit мог создавать другую
геометрию, а variables успешного скрипта терялись при восстановлении. Они
исправлены и покрыты регрессиями, включая loop/старый кандидат/ошибку после
оценки и pure-variable update без новой оценки. Описание контракта и нового
экспорта — в [checkpoints.md](checkpoints.md). На исправленном runtime
живой Linux-цикл 1→2 этажа использовал variables после commit: 5 LLM-вызовов,
2 оценки, 68.30 с. Экспорт обоих кандидатов воспроизвёл snapshots и IDs.

Дополнительно исправлен P2 из повторного ревью `e94f895`: перехваченный overflow
журнала теперь полностью откатывает операцию до commit, включая revision,
выделенные IDs и учёт байтов. Точный пример с лимитом 2000 даёт completed,
одну оценку и 11 операций при revision 11; native replay проходит. С обычным
лимитом выполняются все 50 переносов. Необработанный overflow откатывает
попытку, сохраняя оценённые checkpoints/отчёты. Пройдены 128 детерминированных
тестов на macOS и Linux; новый live LLM для этого исправления не запускался.

## Что показали живые проверки

- Feedback: реальная оценка первого кандидата, отдельный Reviewer-патч с одного
  до двух этажей и выбор нового оценённого кандидата.
- Courtyard: реальный запрос Architect, три этажа и сохранённое отверстие.
- Оба сценария выполнены независимо на macOS и Linux до последнего сокращения
  отличий. Они проверяют соответствующую версию; текущие роли и контракты
  дополнительно покрыты регрессионными тестами.
- После сокращения отличий: Linux-пилот реального контура 1028279 завершён
  с `floor_count=2` и `site_match=1`; footprint 560 м², mesh 3360 м³ и замкнута.
  Первая попытка без передачи контура завершилась неудачей и также учтена.
- Реальные CoMa requirements 1627: 14 этажей, floor_height 3.714 м,
  total_area 24806.020334769833 м²; после уточнения пустой начальной сцены
  живой Linux-прогон дал ошибку этажности 0, ошибку площади ≈1.47e-16,
  SiteMatch ≈1 и IdIoU 1. Оба исхода и raw metrics сохранены.

| Общий датасет и реальные цели | Полный benchmark-датасет не подключён. Адаптер полных числовых требований и алиаса площади реализован; общий split и одинаковые defaults ещё не согласованы. |
| Серия реальных участков | Проверен один реальный контур с диагностическими целями; серия 5–10 участков ещё не выполнена. |
| Несколько требуемых зданий | Runner отклоняет такие rows. Текущий массинг может содержать много экструзий, но это не коллекция зданий с разными requirement IDs. |
| Общий benchmark | Нет итогового сравнения методов, общего отчёта по датасету и подтверждения качества исходной статьи. |
| Полный набор оценщиков | Проверенные FloorCount/SiteMatch не означают проверку девяти общих или физических метрик. Возможные ошибки общих оценщиков требуют отдельной проверки. |

## Границы поведения

`completed` — решение Reviewer завершить запуск, а не универсальный признак
выполнения всех требований. Проверять нужно выбранный кандидат и его отчёт.
`scene.json` хранит последнюю принятую сцену исполнителя; при выборе старого
кандидата она может отличаться от `selected_massing.json`.

Ограниченный AST-worker не является полноценной OS sandbox. Внешний evaluator
считается доверенным. Уже созданные кандидаты и выполненные оценки остаются
в архиве при последующей ошибке скрипта; сцена и переменные этой попытки
откатываются вместе.

Codex CLI — отдельная адаптация транспорта со своим служебным контекстом и
JSON-конвертом. Его usage не равен длине промптов Text2BIM. Для подписочных
запусков денежная стоимость не вычисляется; default-модель не подходит для
зафиксированного сравнительного эксперимента.

## Текущий приоритет

Поддерживаемый сценарий — один массинг:
задание → генерация → реальная оценка → при необходимости патч → результат.
Этот путь реализован и проверен. Одного JSON sample достаточно; полный test
split не нужен. Команда runner принимает `--sample` (`--dataset` — алиас).
